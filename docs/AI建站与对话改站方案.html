01 / 现状判断

链路已经跑通，
但还差一个“可对话”的入口。

现有工程已经完成了设计稿取数、规则转译、可视化预览和 WordPress 写入。真正的产品跃迁，不是再做一个转换按钮，而是把 Elementor 页面变成 AI 能理解、能安全修改的“结构化站点”。

Core Insight

AI 建站的关键，不是让大模型直接写 HTML，而是让它在受约束的站点模型上做决策。

设计稿负责“还原”，编译器负责“确定性”，大模型负责“理解意图”。三者分开，才能同时获得高保真、可编辑和可回滚。

01 / DESIGN
设计即输入
MasterGo / Figma 设计稿、需求简报、模板都可以成为建站起点。
02 / COMPILE
编译即交付
输出 Elementor 原生 Container / Widget，不是锁死的页面快照。
03 / CONVERSE
对话即修改
客户说人话，系统生成小范围 ChangeSet，预览确认后发布。

02 / AI 建站主方案

三种入口，
一套站点编译器。

不管客户从设计稿、需求简报还是现有模板开始，最终都进入同一条编译流水线：规范化 → 语义规划 → Elementor 生成 → 质量检查 → 交付发布。

Mode A · Design-to-Site

把设计稿还原成可编辑的网站

适合已有品牌视觉、需要快速落地的客户。保留设计意图，同时把“看起来像”升级为“在 Elementor 里真的能改”。

桌面画板推导平板 / 移动布局；多列转堆叠，装饰层按规则隐藏或降级。

Elementor 编译与校验
生成 Container 树，执行 JSON Schema、Widget 白名单、ID 唯一性和可导入性校验。

从一句需求，生成完整页面骨架

适合还没有设计的客户。AI 先做信息架构和内容规划，再交给编译器产出页面；设计感来自品牌模板与设计系统，而不是随机生成。

品牌套用

分块生成与组装

Mode C · Template-to-Brand

选一个模板，改造成客户自己的网站

适合已有成熟版式、需要批量复制的交付场景。核心不是“换颜色”，而是识别模板中的可变量，把结构复用到不同品牌和行业。

01
模板语义标注
标记标题、正文、图片、按钮、卡片、价格、评价等变量，形成模板 Schema。
02
品牌资产注入
Logo、色板、字体、图片风格、语气与 CTA 文案统一注入，保留原始布局节奏。
03
行业内容适配
根据客户行业重写 Section 标题与卖点，检查内容长度对布局的影响。
04
批量页面组装
首页、关于、产品、案例、联系页共用导航与 Footer，统一全局 Token。
Delivery

可交付产物

04 / 目标架构

四层架构，
把对话关进安全的笼子。

对话层只提出意图与操作，编译层负责生成合法的 Elementor 结构，交付层负责版本和安全。每一层都能独立测试、独立演进。

安全边界：LLM 永远拿不到 WordPress 管理员密码，也不能直接执行插件代码；它只能调用受控工具，所有写操作都必须经过变更集与审批。

为什么是 ChangeSet，而不是“让 AI 重写整页”？

整页重写会产生不可解释的漂移：客户只改一个标题，结果布局、图片、链接全变了。ChangeSet 把修改限定为可审查的最小操作，天然支持冲突检测、逐条确认和版本回滚。

index
站点语义模型：为每个页面、Section、Widget 建立稳定 ID 与角色，例如 home.hero.title。
patch
变更操作：update_text / update_style / swap_image / reorder / insert / remove / toggle_visibility。
guard
执行约束：节点归属、Widget 类型、文本长度、颜色格式、链接协议、资源域名全部白名单校验。
audit
审计与回滚：记录对话、变更集、预览截图、审批人、发布时间与回滚点。

05 / 落地路线

先做最小闭环，
再让客户真正用起来。

建议把“客户能改、能看到、能撤回”作为第一优先级，而不是一开始就做多租户、全站生成和复杂动效。8–12 周可以形成可演示、可试用的版本。

P0 / CONVERSATION MVP2–3 周

对话改站最小闭环

让一个真实客户完成：说一句话 → 看到预览 → 确认 → 发布 → 撤回。

  • 稳定语义 ID：page / section / widget 三级定位
  • ChangeSet Schema 与白名单执行器
  • 只支持 6 类操作：改文案、改颜色、换图片、调顺序、显隐、改链接
  • 聊天面板 + SSE 流式回复 + 变更预览
  • WP 插件新增 snapshot / apply / rollback
  • 单页、单站点、管理员审批
验收：客户改标题 / 品牌色，1 分钟内看到预览，可一键撤回。
P1 / PRODUCTION4–6 周

生产可用与视觉质量

把演示变成可交付产品，解决“看起来有没有坏”和“谁能改什么”。

  • Playwright 截图与视觉回归对比
  • 响应式三档独立校验
  • 角色权限：管理员 / 编辑 / 客户审阅
  • 页面版本树、差异对比、按版本回滚
  • 导航、Footer、全局色彩与字体同步
  • 图片替换、媒体库与资源完整性检查
  • 对话上下文记忆与多轮澄清
验收：变更预览通过率 ≥ 90%，发布失败可自动回滚。
P2 / PLATFORM6–8 周

多站点与规模化交付

从工具升级为平台，支持代理商与批量客户。

  • 多租户、站点隔离、用量与配额
  • 整站页面批量生成与共享导航 / Footer
  • 行业模板库、品牌 Kit、区块复用
  • 多语言内容生成与本地化
  • 发布审批流、邮件通知、客户空间
  • A/B 版本、转化埋点与页面表现分析
  • 插件版本管理、站点健康检查
验收：10+ 站点稳定运行，单站交付周期显著缩短。
